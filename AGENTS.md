# AGENTS.md — tmux-opencode

## What this repo actually is

- Three coupled pieces:
  - OpenCode plugin in `src/` -> builds to `dist/index.js`
  - shared daemon in `src/daemon/` -> owns popup-visible SQLite state and Unix-socket RPC
  - tmux plugin entrypoint `tmux-opencode.tmux` -> shell/Python popup flow in `scripts/`
- Edit source, not build output. `dist/` is generated by `npm run build`.

## Commands that matter

- Install deps: `npm install`
- TypeScript verification:
  - `npm test`
  - `npm run typecheck`
  - `npm run build`
- Shell/integration checks are **not** wired into `package.json`; run them directly:
  - `bash test/render_status_test.sh`
  - `bash test/prune_stale_snapshots_test.sh`
  - `bash test/show_popup_test.sh`

## Highest-value files

- `src/index.ts` — real OpenCode plugin entrypoint; owns event -> daemon mutation behavior and visible-root tracking
- `src/daemon/store.ts` — SQLite schema and current-state reads/writes
- `src/daemon/server.ts` — Unix socket daemon server and request routing
- `src/daemon/client.ts` — daemon client used by plugin and CLI entrypoints
- `src/daemon-entry.ts` — long-running daemon process entrypoint
- `src/daemon-cli.ts` — CLI bridge used by shell popup scripts
- `src/tmux.ts` — tmux session/window/pane discovery and window renaming
- `tmux-opencode.tmux` — TPM entrypoint and default keybinding
- `scripts/show_popup.sh` — `tmux display-popup` wrapper
- `scripts/popup_command.sh` — popup control flow: daemon `prune-and-list` with one `ensure-running` retry -> render machine rows -> `fzf` -> jump tmux client/window/pane
- `scripts/render_status.py` — actual renderer implementation
- `scripts/prune_stale_snapshots.py` — legacy file-snapshot pruning logic still covered by shell tests; not the popup source of truth

## Wiring / execution flow

- OpenCode events land in `src/index.ts`.
- `src/index.ts` sends normalized mutations through `src/daemon/client.ts` to the daemon socket.
- The daemon stores popup-visible state in `${TMUX_OPENCODE_DAEMON_DIR:-${TMPDIR:-/tmp}/tmux-opencode-daemon}/status.sqlite` and listens on `daemon.sock` in the same directory.
- tmux popup path is:
  - `tmux-opencode.tmux`
  - -> `scripts/show_popup.sh`
  - -> `scripts/popup_command.sh`
  - -> `node dist/daemon-cli.js prune-and-list`
  - -> on failure: `node dist/daemon-cli.js ensure-running` once, then retry `prune-and-list` once
  - -> `DAEMON_JSON=... TMUX_OPENCODE_RENDER_MODE=machine bash scripts/render_status.sh`
  - -> `scripts/render_status.py`
  - -> `fzf`
  - -> `tmux switch-client` / `select-window` / `select-pane`

## Behavior that is easy to break

- Root-session visibility is local to one plugin instance. `src/index.ts` tracks a single `visibleRootSessionID` and replaces/removes that root when sessions are selected, created, or replaced.
- `session.status` only maps `busy`/`retry` -> `working` and `idle` -> `idle`; streaming events are intentionally ignored.
- Child rows are only upserted if the parent session is visible in the plugin instance.
- Root exits/deletes send `delete-session-tree` daemon mutations; child exits/deletes are intentionally ignored.
- Root rows record `processPID`; stale pruning rules apply only to roots and cascade through descendants.
- Popup startup is daemon-mediated via `prune-and-list`; if the first call fails, `scripts/popup_command.sh` runs `ensure-running` once and retries once before failing.
- Popup selection depends on stored `tmuxSessionID`, `tmuxWindowID`, and `tmuxPaneID`; rows without full tmux metadata render, but selection fails safely.
- `src/index.ts` also renames the tmux window for root sessions to the derived project name when tmux metadata is available.

## Verified doc/source quirks

- Default tmux keybinding is lowercase `o` in `tmux-opencode.tmux`, not uppercase `O`.
- `scripts/render_status.sh` is only a bash wrapper; the renderer logic lives in `scripts/render_status.py`.
- The repo docs mention Python 3.10+, but the executable scripts simply call `python3`; if behavior matters, trust the scripts/tests.

## Useful focused checks

- Renderer only: `TMUX_OPENCODE_STATUS_DIR="$PWD/.tmp-status" bash scripts/render_status.sh`
- Machine rows from daemon JSON: `DAEMON_JSON='{"type":"rows","rows":[]}' TMUX_OPENCODE_RENDER_MODE=machine bash scripts/render_status.sh`
- Interactive popup flow: `TMUX_OPENCODE_DAEMON_DIR="$PWD/.tmp-daemon" bash scripts/popup_command.sh`

## TypeScript/build boundaries

- `tsconfig.json` builds only `src/**` into `dist/`.
- `src/__tests__` is excluded from build output but covered by `npm test`.
- Package is ESM (`"type": "module"`) and strict TypeScript is enabled.
